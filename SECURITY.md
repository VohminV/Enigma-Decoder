# Security Policy — Enigma Decoder

## Криптографический дисклеймер

Enigma — **исторический шифр, скомпрометированный в 1940-х годах**.
Он не обеспечивает конфиденциальность против современного противника.
Проект предназначен **только для образования, исторических исследований
и анализа перехватов**. Не шифруйте им реальные секреты, пароли,
персональные данные, коммерческую или государственную информацию.
Для реальной защиты используйте AES-256-GCM / ChaCha20-Poly1305 / TLS 1.3.

## Как сообщить об уязвимости

- Откройте приватный security advisory в GitHub (предпочтительно)
  или напишите мейнтейнеру напрямую.
- Укажите: версию, ОС, шаги воспроизведения, влияние, PoC с вымышленными
  данными (не присылайте реальные персональные данные).
- Мы подтвердим получение в течение 7 дней и выпустим фикс/митигацию.
- Не публикуйте уязвимость до согласования срока раскрытия (обычно 90 дней).

## Что считается уязвимостью здесь

- RCE, произвольная запись файлов вне выбранного пользователем пути,
  выполнение shell-команд из пользовательского ввода.
- Обход валидации Enigma-конфига, приводящий к silent wrong crypto.
- Утечка key-material (кольца/позиции/штекеры/тексты) в логи/артефакты.
- DoS через отсутствие лимитов (текст/файл/изображение/PDF/sweep).
- Утечка секретов через репозиторий/артефакты/CI.

## Что НЕ считается уязвимостью

- «Enigma можно взломать» — это известное свойство исторического шифра.
- Неточности G/K/D проводок без нового первичного источника
  (оформляйте как issue с источником, а не как CVE).
- Отсутствие сетевой auth/rate-limit: приложение локальное single-user
  и не предназначено для публикации в сеть без отдельной изоляции.

## Правила безопасного использования

1. Запускайте локально, не выставляйте GUI/CLI в интернет.
2. Не вставляйте в логи/скриншоты/issue реальные чувствительные тексты.
3. Проверяйте импортируемые `keys.json`: GUI валидирует схему
   (`keydb.validate_db`), битые файлы отклоняются.
4. Соблюдайте лимиты: текст 1M символов, файл 5 МБ, БД 10 МБ,
   изображение 50 МП / 30 МБ, PDF DPI 72..400.
5. Не храните реальные секреты рядом с исторической базой ключей.

## Логирование и секреты

- Логи (`enigma_gui.log`, ротация 1 МБ × 3) содержат только типы ошибок,
  не значения колец/позиций/штекеров/текстов.
- Секреты/токены/API-ключи в коде запрещены; конфигурация — только
  локальные пути через диалог выбора файла и `QSettings` (тема/профили).
- Исторические ключи `keys.json` — публичные архивные данные, не секреты.

## Зависимости

Релиз фиксирует манифест `pyproject.toml`; dev-reference `py-enigma==1.0.2`
используется только в тестах и не импортируется production-кодом.
Перед релизом выполняется `pip audit` (см. CI, job `audit`, допускает
сеть только в этом job).
